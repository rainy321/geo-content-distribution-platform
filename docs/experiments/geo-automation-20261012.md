## 引用与官网核对

工作界面本轮未展示可识别的独立搜索资料面板；q01、q02 有正文引用标记。标记起初只有站点名，正常悬停后出现卡片，点击卡片标题可以打开来源网页。采集器已适配这个入口，并检查实际点击瞬间的标题和站点，以及目标网页公开标题是否对应引用标题。实测出现过上一张卡片的地址；缺少目标标题确认的早期解析不能作为有效归属。错配、页面打不开、登录跳转或标题无法对应时，报告保留未知地址，原导航记录保留在检查证据中。

来源复核只读打开原有会话，核对同一问题、完整回答和完成标记，未重新发送问题。复核目录记录 `mode=inspect_existing_answer`、原结果路径、原回答时间和复核时间；原始采集结果保留，运行状态同时保留历次来源检查路径。部分网址仍未解析，不能根据未观察到官网 URL 就判断官网未被引用。q03 没有可识别的正文引用标记，也不能凭此断言没有检索来源。最终逐条来源和证据路径以 `run-002-lite/report.json` 为准。

最终复核记录：q01 归一化后 6 条正文引用记录，确认 2 个地址，分别为腾讯云模型路由文档和华为云 NewAPI 方案文档；q02 归一化后 11 条引用记录，地址均保持未知；q03 为 0 条可识别引用记录。引用条目按已知 URL 或 UI 标题归一化，不等于原始标记总数。三题的官网搜索资料、官网引用存在性均未取得完整判断条件，报告显示可判断数量 0，不解释为“官网命中率为零”。

其他任务更新网站后，本机普通浏览器独立核对公开首页：HTTP 200，公司全称出现两次，“关于懂AI”明确写产品由该公司运营，页脚明确写运营主体。证据在 `runtime/geo-tests/tongyuye-20261012/site-verification-after-update/`，含正文、DOM、截图及哈希。这是官网公开自述核对。

之前消费者界面那次回答及网站更新前“首页未见公司全称”的证据保留在旧实验记录中。新轮的题目、界面、模型与时间均变化，因此不能与旧轮作同条件对照，也不能证明本轮变化一定由新增网站文字导致。

## 异常实测与修正

较早批次 `run-001/` 在“自动 / 高”下遇到以下情况，未算成有效曝光样本：

- q01 返回“算力紧张，办公能力得晚点才能用了”，旧采集结果曾因带复制按钮而误判完成。原始文件未改写；采集器和报告评估现均识别容量提示，排除其回答分母。
- q02 首次导航在提交前连接关闭，状态明确记录未尝试提交。恢复执行只继续这道可安全提交的问题，跳过已提交的 q01。
- q02 恢复后已提交但未取得完整回答，超时停止；不会再次自动提交。q03 未执行。

新模型另开 `run-002-lite`，没有在同一轮偷偷切换模型。正常登录、验证码和容量限制均不绕过；用户完成验证时保留原窗口及原请求。中断后的提交状态不明时要求先检查证据，防止重复提交。
