# 从 AI 搜索采集到内容发布

“采集驱动内容”将报告作为编辑工作的起点：原始问题与来源 → 内容任务单 → 核对写作事实 → 按渠道生成稿件 → 内容库审稿 → 现有发布中心 → 同题复测。当前采集平台仍为豆包；写作可选择专用豆包会话或系统设置中的 AI API。

## 软件内的使用方式

1. 在“AI 搜索测试”的报告上点击“用本报告制定内容任务”，或从“采集驱动内容”选择已保存报告。
2. 软件保存基线快照与原计划指纹，自动关联同名品牌项目。有效问题先变成采集待办，明确标记尚未经过 AI 策划；失败题不会变成“零曝光”选题。
3. 点击“豆包分析采集并制定选题”或“用已配置的 AI API 策划”。AI 必须引用真实问题编号、观察到的来源编号，给出选题、提纲和待补资料，不允许编造采集依据。
4. 填写并核对事实库，每行“事实 | 来源网址”。无公开网址的资料只能作为运营方说明，不能冒充独立验证。采集回答不会自动进入事实库。
5. 选择选题和渠道，生成知乎、今日头条、百家号、搜狐号、小红书或官网稿。稿件以草稿状态进入现有内容库，并记录采集基线、原始问题、写作事实和生成来源；编辑器可返回查看这些依据。
6. 人工审稿并标为就绪后，进入现有发布中心选择账号、素材和发布时间。官网稿可导出交给网站编辑。保留现有账号绑定、平台能力、频率与发布确认流程。
7. 任务单回读关联文章的发布任务，只有真实成功且有有效结果网址的任务计入发布链接。演示任务不计入。
8. 按原计划开始新一轮复测，或关联已有复测报告。只有原问题、界面、实际模型标签、采集先后次序符合条件时才显示配对观察值；失败题不补零，来源不可判断时仍为未知。

继续优化时，用这份复测报告再次建立内容任务单，下一轮 AI 选题就以新的回答和来源为依据；上一轮的稿件、事实快照和发布记录仍可追溯。

## 数据与一致性

数据库增加 `geo_content_cycles`、`geo_content_drafts` 和 `geo_content_retests`。任务单、事实库、文章关联与复测记录保存在桌面固定数据目录内，不依赖前端内存。

文章与采集关联在同一事务内保存。相同任务单、选题、事实与渠道已有草稿时，不再次请求 AI，也不重复创建文章。修改事实或选题后生成独立输入版本；旧稿和旧事实快照保留。AI 请求期间资料变化时，不用旧结果覆盖新资料。所有稿件先进入待审状态，AI 输出不会自动触发真实发布。

桌面内容生成证据保存在 `geo-content/evidence/`，角色为 `content_editing_not_exposure_test`，不进入曝光统计。关闭软件、登录或人工验证异常仍沿用原生任务持久化与不自动重发机制。

## 观察与效果的区别

文章来源可以追溯到哪次回答、哪道问题、哪条事实。来源标题与可见网址用于提出编辑假设，不表示网页正文已经核验，更不表示在该平台发帖一定被豆包收录。事实来源的提供方确认也不等于软件独立验证。

复测分别展示自然提及、点名核验和官网引导核验；官网正文引用仅比较双方都可判断的题目。公开链接未在可见引用中出现时，不解释为未被索引。账户、地区、时间变化和索引时滞等仍可能影响结果，因此不能把单轮变化说成发布带来的因果效果。内容库的规则评分也不等于实际曝光。

跨平台方法参考：[Bing 关于用被引用页面和查询线索改进内容的说明](https://blogs.bing.com/webmaster/2026/2/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview/)。它支持用主题与来源观察指导内容完善的做法，不是豆包排名规则。
