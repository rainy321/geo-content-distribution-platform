# 从 AI 搜索采集到内容发布

默认“开始优化”以品牌 → 搜索基线 → 内容 → 发布 → 反馈五步串起软件。“采集驱动内容”保留详细任务单：原始问题与来源 → 内容任务单 → 核对写作事实 → 按渠道生成稿件 → 内容库审稿 → 发布或辅助填写 → 同题复测。当前采集平台仍为豆包；写作可选择专用豆包会话或系统设置中的 AI API。

新增“来源投放目标”：从观察到的具体来源栏目选择目标，或登记小众平台，保存独立会话、内容规范和编辑框配置。可按该目标生成稿并将已审稿文章辅助填写到浏览器；通用接入当前不自动提交。官方文档和没有网址的标题不能冒充已验证的开放投稿平台。参见[来源驱动分发的实现路径与限制](./source-driven-distribution-roadmap.md)。

## 软件内的使用方式

1. 默认“开始优化”按品牌 → 搜索基线 → 内容 → 发布 → 反馈推进。也可在“AI 搜索测试”的报告上点击“用本报告制定内容任务”，或从“采集驱动内容”选择已保存报告；历史报告带原时间，不冒充新采集。
2. 软件保存基线快照与原计划指纹，自动关联同名品牌项目。有效问题先变成采集待办，明确标记尚未经过 AI 策划；失败题不会变成“零曝光”选题。
3. 点击“豆包分析采集并制定选题”或“用已配置的 AI API 策划”。AI 必须引用真实问题编号、观察到的来源编号，给出选题、提纲和待补资料，不允许编造采集依据。
4. 逐条录入并核对事实与来源网址。同品牌旧资料可作为待核对候选复用，新轮必须重新确认；采集回答不会自动进入已确认事实。无公开网址的资料只能作为运营方说明，有网址的运营方自述也不等于独立验证。
5. 选择选题与“通用渠道”或“已接入目标”，生成知乎、今日头条、百家号、搜狐号、小红书或官网稿。已接入目标使用该目标的风格、长度和规范；来源中出现某平台不代表已取得其投稿权限。稿件以草稿状态进入内容库，保留基线、问题、事实、目标及配置版本。
6. 人工编辑、核对内容与声明并标为就绪。已有对应文章发布能力的目标可桥接发布中心，继续选择账号、素材与发布时间，并显式确认；通用目标可打开配置的浏览器辅助填写，最后由用户在站内检查和提交。官网稿可导出交给网站编辑；导出和填写均不计为已发布。
7. 任务单回读关联文章的发布任务，只有真实成功且有有效结果网址的任务计入发布器回报的发布链接，演示任务不计入。人工提交的具体公开链接单列为“运营方自报”，保留未独立核验的证据级别；平台接收、审核通过和公开可读仍分别核对。
8. 按原计划开始新一轮复测，或关联已有复测报告。只有原问题、界面、实际模型标签、采集先后次序符合条件时才显示配对观察值；失败题不补零，来源不可判断时仍为未知。

继续优化时，用这份复测报告再次建立内容任务单，下一轮 AI 选题就以新的回答和来源为依据；上一轮的稿件、事实快照和发布记录仍可追溯。

## 数据与一致性

任务单、事实库、文章关联、运营方自报链接与复测记录保存在桌面固定数据目录内，不依赖前端内存。品牌项目隔离；同一篇文章的目标、选题、基线和时间可追溯，不能拿其他品牌或历史轮次的引用补成本轮证据。

人工在目标平台完成提交后，可登记具体公开文章链接与实际提交时间，作为“运营方自报”记录。必须匹配该目标的发布网址范围，不能只填首页，也不能倒填到基线之前。它与发布器实际成功回报分开显示；缺少公开链接、仍在平台处理或不确定是否提交的任务不会冒充发布成功，软件不会自动重发。

真实头条任务停在“处理中”时，可点击“核对平台结果”，用绑定账号的正常可见会话打开作品管理。软件只点击唯一标题、提交时间窗口及已发布状态相符的实际链接，再核对公开标题、时间、AI声明与完整正文；不编辑或再次提交。正常登录和验证由账号持有人完成，布局、全文、时间或任务授权变化时仍保留未知。核对记录与原提交证据分开保存。

文章与采集关联在同一事务内保存。相同任务单、选题、事实与渠道已有草稿时，不再次请求 AI，也不重复创建文章。修改事实或选题后生成独立输入版本；旧稿和旧事实快照保留。AI 请求期间资料变化时，不用旧结果覆盖新资料。所有稿件先进入待审状态，AI 输出不会自动触发真实发布。

真实发布授权绑定已审稿内容、文章、渠道、账号及分发配置，服务端检查审稿状态。排队后修改文章或撤回审稿会阻止旧任务执行；失败后重试需要重新审稿和确认，不自动重发。关闭窗口或验证中断保留已知提交阶段；是否已提交不明确时先核对平台结果。桌面程序允许用户显式确认的单篇真实发布，不会自动开启后台发布调度；环境明确禁用真实发布时仍尊重禁用设置。作品声明、封面、原创权益与外链等还须按该平台实际页面要求检查。

桌面内容生成证据保存在 `geo-content/evidence/`，角色为 `content_editing_not_exposure_test`，不进入曝光统计。关闭软件、登录或人工验证异常仍沿用原生任务持久化与不自动重发机制。

内部出题、研究和写稿资料以原文保真方式提交，并保存发送前读回和发送后证据；普通曝光问题保持原题。发送前核对不通过会明确提示问题尚未发送。已发请求未能确认完成时保存失败证据；若人工核对后恢复，单独标明恢复依据与人工参与，不改写原始失败文件。

## 观察与效果的区别

文章来源可以追溯到哪次回答、哪道问题、哪条事实。来源标题与可见网址用于提出编辑假设，不表示网页正文已经核验，更不表示在该平台发帖一定被豆包收录。事实来源的提供方确认也不等于软件独立验证。

复测分别展示自然提及、点名核验和官网引导核验；官网正文引用仅比较双方都可判断的题目。公开链接未在可见引用中出现时，不解释为未被索引。账户、地区、时间变化和索引时滞等仍可能影响结果，因此不能把单轮变化说成发布带来的因果效果。内容库的规则评分也不等于实际曝光。

反馈会区分纯采集观察、条件不一致、复测早于提交、提交时间未知和发布后观察。后台“已委托调研，稍后回复”等占位内容不作为有效回答；读取旧报告时按当前规则保守排除，保留原始文件及时间，来源不可判断时仍显示未知。

只读来源复查只补来源视图，明确标记“原回答后核对”及复查时间；原问题、回答、采集时间、计划和文件摘要保持不变。失败或不可用回答不会因补回网址变成有效基线，较早轮次的来源也不会自动并入较新轮次。

已核对的平台公开时间与软件完成核对的时间分别保存；复测按前者判断先后。平台只显示分钟时，同一分钟内的回答不能证明晚于实际发布，保留时间未知。旧任务缺少平台时间时仍沿用原发布器完成时间并标明依据。头条公开链接仅在严格 HTTPS 主机、相同数字文章编号且无用户凭据、无非默认端口时，比较其 article/item 和跟踪参数形式是否代表同篇；原始网址保留，其他平台继续精确比较。

## 当前真实验收进度（2026-10-20）

已完成一次干净的自动出题及三题有效采集，并对较早报告补回部分今日头条、CSDN 来源网址。本次文章闭环使用较早任务单，保留其中官网核验题原失败；分析存在人工证据恢复，稿件由一次提问返回后按严格证据恢复，再经人工编辑。

一篇头条文章已公开，随后通过作品管理及公开全文的只读核对将“处理中”任务结案为成功，没有再次提交。平台显示公开时间 04:09（UTC+8），复测于 04:14–04:22 取得三题有效回答，后来核对结果不会改写实际公开时间。自然发现与点名身份核验分别只有一题可配对，提及率为 0→0 与 1→1；官网核验因原题失败无共同有效题，仍为未知。自然发现题来源采集有缺项，尚未观察到新文章引用，不能解释为未被索引或证明有效、无效及因果。

这一轮验证了有人参与的“采集依据→写稿审稿→真实发布→只读核对→同题反馈”链路，不是全程无人自动。平台默认权益勾选保护在此次发布后修复并做本地回归，修复后未再次真实发布；不能将首篇成功当作新保护逻辑已实站通过。
