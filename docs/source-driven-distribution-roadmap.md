# 来源驱动分发：桌面软件的实现目标与路径

目标是让软件回答“这条用户需求，应该去哪里提供什么内容，以及当前账号能自动做到哪一步”，并实际执行可验证的步骤。

核心路径是**用户问题 → 实际回答与引用 → 具体栏目及目标能力 → 适配内容 → 可追溯发布结果 → 同题反馈**。先观察平台是否引用该来源，再判断该栏目是否允许客户创作、当前账号是否有权限，以及软件是否具备对应能力。厂商文档、转载新闻和开放社区各有不同边界；不能仅凭域名出现就自动注册、生成广告并提交。

## 本次实现

1. 把采集来源按**具体域名与栏目路径**转换为投放研究线索。正文引用和界面来源按问题、网址去重，只使用有效回答；保留证据编号。官方文档、客户官网、开放内容社区候选、未知网站、缺少网址分别处理。
2. 预置知乎、头条、百家号、搜狐、小红书、腾讯云开发者社区、CSDN、博客园的部分公开来源面。它们是来源识别与接入起点，**不是新增了八个经过实站验证的发布器**。入口、账号准入和平台现行规则仍要检查。标题提到平台但没有网址时，只标“未核实标题线索”。
3. 客户可添加小众平台，无需每次修改软件代码。保存来源匹配范围、正常注册/登录入口、编辑器入口、内容风格、规则原文网址、标题/正文长度与内部操作频率阈值。配置按客户隔离、版本化保存。
4. 生成稿使用所选平台的内容规范，保存目标平台、配置版本、实际匹配的来源编号和事实依据。选题没有匹配来源时明确标为手动选择。AI 生成稿超限时拒收，配置在生成途中变化时拒收过期稿。
5. 桌面软件为每个客户的平台接入记录建立独立浏览器目录。用户正常注册、登录、实名和验证，关闭后保存会话；“会话保存”不冒充“登录/投稿权限验证通过”。不读取个人默认浏览器的登录资料，不打包客户会话。
6. 配置两个普通 CSS 编辑框后，可把已审稿、标记就绪的对应平台稿自动填入**唯一、可见、空白、可编辑**的标题和正文框，并回读检查。支持普通输入框及 contenteditable。最后在站内检查和提交；网站可能自行保存草稿。复杂富文本、图片上传、iframe 需要专用适配器。
7. 原子保存尝试，再打开编辑器。跨客户、跨目标、未审稿、超长度、重复尝试、滚动 24 小时阈值和间隔不符都会阻止执行。出现已识别的验证/账号限制提示、跳转到其他域名、布局失效、已有草稿或中断时暂停并保留记录。重启不自动重放；人工检查并明确恢复也不会清空频率记录。风险提示识别目前为有限规则，不能覆盖所有平台。
8. 已登记的目标稿可桥接对应的内置文章发布器，保留原文章、选题、事实、目标版本和采集周期。来源观察范围、登录/编辑入口和发布后公开网址范围分别配置，例如一个平台的问答栏目与文章栏目可能在不同子域名。服务端检查实际渠道能力、公开网址范围及目标配置摘要；不一致就停止。发布前仍需绑定可用账号、审稿和显式确认，自定义目标阈值与原发布器阈值同时生效。已有适配器、实站提交成功和公开结果已验证分别记录。
9. 默认五步界面把报告、来源候选、写作、发布与反馈串在一个品牌上下文中。品牌数据落在固定本机目录；恢复时处理服务器变更与本机未保存编辑冲突。历史报告带原时间，失败题与后台占位回答不计为零曝光。

另修复本机 Edge 无法启动时的回退：只在浏览器启动失败、尚未打开网页时尝试本机 Chrome，使用独立的 `-chrome` 会话目录。原 Edge 会话保留；Chrome 首次仍可能需要用户正常登录。该回退同时用于桌面的豆包入口与通用平台浏览器，不用于验证、登录失败或填写/提交后的重试。

入口：桌面软件 → 开始优化 → 内容 → 接入或配置目标平台；详细设置也可从“采集驱动内容 → 来源投放目标”进入。转入内置发布器仍需绑定其对应账号，不能把新增浏览器会话直接视为已有发布器账号。

## 当前验收边界（2026-10-20）

一次干净的自动出题及三题基线采集已完成；较早报告的只读来源复查补回今日头条、CSDN 等部分网址，保留历史轮次身份与时间。本次文章闭环使用较早任务单，未替换其中失败的官网核验题。分析曾人工核对证据后恢复；稿件由一次提问返回，经严格原文证据恢复和人工编辑。

一篇头条文章已公开。原任务因未得到最终回报停在“处理中”，后来经软件只读核对唯一作品卡、实际公开链接、发布时间、AI声明及全文后记为成功，没有再次提交。独立证据保留原提交记录、实际公开时间和结果核对时间。随后三题复测均取得有效回答；自然发现与点名身份核验各有一题可配对，提及率分别 0→0、1→1，官网核验无共同有效题。来源采集仍有部分缺项，尚未观察到新文章引用，不能推断收录或优化效果。

这是一轮有人参与的真实链路验收，不能称完全无人自动或代表所有平台稳定可交付。平台默认权益勾选的保护是在首篇公开后修复的，虽有本地回归，尚未再真实发布验证；应与已经实测的提交和只读结果核对分别列明。

## 产品架构与实施顺序

| 顺序 | 要完成的产品目标 | 实现路径与验收条件 |
| --- | --- | --- |
| 1，当前基础 | 来源指导目标；长尾平台可登记并辅助执行 | 已有识别、配置、目标稿、辅助填写和内置发布桥接代码。区分可识别、已配置、会话已保存、可填写、可提交与结果已验证；实际账号与站点能力仍需逐项实测。 |
| 2，先做少量完整样板 | 从账号授权到发布结果都可验证 | 选真实报告中反复出现、允许客户投稿且适配成本可控的 2–3 个平台；走通授权、素材上传、保存草稿、预检、发布、回读最终链接、审核拒绝和撤回。每个平台记录适配版本与最后实测日期。 |
| 3，官方接口与 CMS | 覆盖大量用户自有站，而非逐域名开发 | 优先 WordPress 等共用协议的 CMS，再接有正式授权方式的平台 API；本机保存可撤销凭据，远端返回文章 ID 和状态后才记成功。当前尚未实现 WordPress 发布器。 |
| 4，未知平台接入向导 | 普通客户不需要懂 CSS | 采集经用户打开的编辑器控件、标签和允许的操作；AI 提议字段映射、风格和规则摘要，用户预览，自动做不提交的填写验证；实施人员发布可维护的版本化平台包。先处理验证码和权限，再验证映射；AI 不获任意执行脚本或盲点发布的能力。 |
| 5，跨平台调度与账号健康 | 能长期运行，故障可定位且可停止 | 目标稿的辅助填写与内置发布共用目标阈值，内置路径叠加账号策略并保存已尝试阶段；结果未知时不自动重发。尚未完成所有平台统一的官方配额读取、规则更新、审核回调和账号健康监控。 |
| 6，效果与迭代 | 知道哪些内容和目标值得继续做 | 来源按问题组、平台、栏目、时间统计；发布后记录 URL、审核与索引状态，再按原问题、原模型复测。比较自然发现与品牌核验，保留未知，不把发布成功当作 AI 已收录，不以单轮变化证明因果。 |

每个平台适配能力应分别记录 `recognize_source / onboard / auth_checked / draft_write / submit / result_verify / media / schedule`，并附验证时间。统一界面根据能力选择官方 API、已验证浏览器适配器或辅助填写。不要把网页任意自动化等同于稳定可交付能力。

## 尚未解决与建议

- **完整来源地址不足**：真实只读来源复查已补回部分厂商文档、今日头条与 CSDN 网址，仍有跳转终止、悬浮卡变化或公开页标题不匹配的地址保留未知。较早一轮的社区与媒体来源，与较新一轮的厂商文档来源分开保存。来源复查绑定原问题、会话、回答内容和原始文件摘要，保留原回答时间并显示后来复查时间；它不是新回答或复测，也不证明该站点允许客户投稿。
- **注册与发布权限**：手机号、实名、扫码、付费或作者审核通常需要用户或平台配合。做一次性接入任务和清晰的待办队列，随后复用可用会话；不把“自动替所有人注册所有网站”作为售卖承诺。
- **长尾编辑器**：目前 CSS 配置仍偏实施人员使用。下一步应优先做控件识别和不提交的测试向导，复杂编辑器沉淀成平台包；提供平台包升级与回滚。此机制尚未实现。
- **风格与内容规则**：当前规范由配置方核对，AI 据此写稿；还没有自动抓取规则更新、完整的平台级广告/敏感词/外链/图片审核器。已确认事实也要区分运营方自述与独立证据，旧事实在新轮重新确认。应保存规则来源和版本，并对缺乏依据、重复铺稿、虚构体验和不适配素材给出具体阻止原因。
- **封号风险**：频率阈值仅限制软件自己的操作，不代表平台允许额度，更不是免封号保证。先以官方授权、少量原创内容、操作停止条件和人工异常处理作为交付标准；没有足够实站数据前不报“封号率下降多少”。
- **桌面交付与持续维护**：账号和素材留在用户本机；可把平台包/规则版本更新与发布器回归验证做成服务。商业上建议“桌面客户端 + 适配器更新服务”，同时明确标准支持与需实施接入的范围，避免售卖一个无人维护的全平台万能发布器。

## 依据

- [WordPress 官方 REST API 认证](https://developer.wordpress.org/rest-api/using-the-rest-api/authentication/)：支持 HTTPS 上的 Application Passwords，可作为通用 CMS 授权路径的依据。
- [Playwright 持久浏览器上下文](https://playwright.dev/python/docs/api/class-browsertype#browser-type-launch-persistent-context)：支持独立目录保存浏览器会话，同一目录不能供多个实例同时使用。
- [今日头条社区规范](https://baike.toutiao.com/detail/236/238/0)及[文章原创规则](https://baike.toutiao.com/detail/242/243/0)：接入、审稿和提交前核对平台当前要求。当前内置文章流程使用“引用AI”作品声明，不替用户申请原创权益；具体权限与审核结果由平台决定。
