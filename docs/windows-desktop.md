# GEO Windows 桌面版交付说明

## 当前交付定位

`GEO-Content-Platform.exe` 是 Windows 本机单用户便携软件，不是正式网站的快捷方式，也不是多租户客户端。它在本机启动 Flask/Waitress 服务，在随机的 `127.0.0.1` 端口提供 API，再由 Edge WebView2 显示内置的 Vue 界面。

本阶段交付对象只有 Windows EXE、校验清单和随附文档；正式网站、网页部署、服务器发布与服务器数据库迁移都不属于这份桌面交付，也不是启动或使用 EXE 的前置条件。

当前产品版本为 `1.2.8`，构建时必须选择不可变的发布 profile：默认 `safe` 版不带真实发布运行时；`authorized_real` 版带经过成品探针验收的真实发布运行面。两种构建使用不同的产物目录和 ZIP 名称，不能靠 Windows 环境变量把 `safe` 版改成真实发布版。EXE 没有安装向导、自动更新器、Windows 服务或开机启动项；同一数据目录一次只允许一个实例运行。

同事交接 ZIP 未包含 `LICENSE` 或 `NOTICE`。在取得权利人的书面内部授权或补齐可核验的许可声明前，包含其 Python 移植算法的构建只用于内部受控 Beta，不作为已完成外部商业分发授权的版本。

面向运营人员的首次使用步骤见 [首次使用](./首次使用.md)，AI 可见度后端契约和算法边界见 [AI 可见度集成说明](./ai-visibility-integration.md)。

## 产品边界

- 延续品牌项目、内容生成、统一内容引擎适配、本地 GEO 规则分、内容库、素材、媒体账号和发布任务逻辑；媒体账号登录与真实执行只在 `authorized_real` 且本机发布运行时就绪时开放。
- 新增 AI 可见度工作台：既可导入已经取得的回答，也可在操作员预览并确认后，对当前配置的一个 OpenAI-compatible 模型顺序采样 1–5 次；返回回答统一交给本机确定性规则完成品牌提及、推荐位次、引用、情感、声量和建议分析。
- 新增本机 GEO 诊断闭环：对项目或内容形成五维基线、P0/P1/P2 缺口、建议动作、目标指标和复测规则。诊断分是本产品的确定性基线，不是搜索平台或模型厂商的官方排名。
- 新增独立“成本账单”界面：可按项目、时间、操作和核算状态筛选模型调用，查看总览、操作/模型/项目拆分与逐笔回执，并导出当前明细窗口。平台登录、上传和发布本身不调用模型时，不伪造“发布 Token”或零成本。
- 手工导入区的 `provider`、`model` 只是样本溯源标签，不触发联网；受控采样区必须填写/选择精确服务地址、模型 ID 和当前会话密钥，并明确勾选外发确认。缺少完整请求级配置且本机也没有完整环境配置时，后端会在联网前拒绝。
- 受控采样每次外发的唯一自然语言内容是操作员填写的 `prompt`。项目、产品、官网、文章、别名、竞品、媒体账号、Cookie、凭据和发布任务不发送给模型；调用只顺序执行 1–5 次，不做并发、定时、后台无人值守或分布式采样。已经由操作员确认并启动的请求在切换路由、重载页面或传输中断后，以原 `request_id` 查询同一持久化请求，不会因此再次调用 provider。
- 选择“保存到本机分析历史”后，问题、回答原文、覆盖项和完整结果会写入本机 SQLite；不保存时不另建分析历史。但真实采样的请求 ID、幂等键和结果仍会持久化，以防断线或重试造成重复调用和扣费。
- 采样在首次调用前建立幂等记录；同键同参数只回放，同键不同参数拒绝。失败、超时或结果不明确时停止后续样本并要求人工处理，不自动重试，不静默生成新键。
- 桌面宿主不会读取正式服务器数据库，也不会把网站上的已有客户或项目数据复制到本机。
- AI 内容创作是另一条功能链路；只有在另行配置模型凭据时才可能调用外部内容模型。不能把“可见度本地分析”理解为整个软件完全离线。

## 运行架构

```text
GEO-Content-Platform.exe
  ├─ 桌面宿主：路径、单实例、生命周期、日志与备份
  ├─ Waitress：仅监听 127.0.0.1 的随机端口
  ├─ Flask：认证、业务 API、SQLite 与安全闸门
  ├─ Vue：内置产品界面
  └─ Edge WebView2：本机软件窗口与当前软件会话存储
```

应用关闭时，桌面宿主会停止安全调度器、内置 HTTP 服务和由本次桌面会话启动并登记的 Bilibili 进程树。它不会按进程名扫描或结束无关程序。程序异常退出后，下次启动仍从 SQLite 持久状态恢复；中断时仍处于平台调用中的任务会转为“已提交、待平台核验”，不会自动重发，启动过程也不会清空现有数据。

## 本机目录

默认根目录为 `%LOCALAPPDATA%\GEOContentPlatform`。标题栏右侧的“本机数据”按钮可以打开该目录。

| 路径 | 内容 | 备份建议 |
| --- | --- | --- |
| `data\geo.db` | 项目、文章、生成记录、可见度历史、账号索引和发布任务 | 必须备份 |
| `media\` | 上传和生成的本机素材 | 需要随业务数据备份 |
| `accounts\` | 媒体账号会话文件 | 敏感；只交给获授权人员 |
| `config\auth.json` | 会话签名密钥、口令盐和摘要 | 敏感；不能公开或单独删除 |
| `backups\` | 经过 SQLite 完整性检查的数据库快照 | 默认保留最近 5 份 |
| `logs\desktop.log` | 桌面启动与生命周期日志 | 故障排查时提供，先检查敏感内容 |
| `webview\` | WebView2 的本机浏览器状态 | 一般不作为业务恢复依据 |

可以通过 `GEO_DESKTOP_DATA_DIR` 或命令行 `--data-dir` 指定隔离目录；该能力主要用于测试或受控运维。使用不同目录会得到完全独立的数据库、口令和单实例锁。

## 登录与本机安全

首次启动必须设置本机管理员口令。口令经随机盐和 600,000 次 PBKDF2-HMAC-SHA256 计算后保存；软件不保存可找回的明文口令。登录状态由 HttpOnly、SameSite=Lax 会话 Cookie 维护，默认会话有效期为 12 小时。

这是应用级访问边界，不是磁盘加密：SQLite、素材和账号文件没有使用应用内静态加密。Windows 管理员、本机恶意软件或能够读取当前用户目录的人仍可能读取这些文件。交付设备应启用 Windows 登录保护、磁盘加密和最小权限。

## 数据库备份

- 已有数据库非空时，每次启动会先创建一份 SQLite 在线快照，并执行 `PRAGMA integrity_check`。
- 登录后点击标题栏的“立即备份”，可以按需创建相同类型的快照。
- 自动和手动数据库备份共用 `backups\` 目录，默认只保留最新 5 份 `geo-backup-*.db`。
- 数据库快照不包含 `media\`、`accounts\`、`config\`、`logs\` 或 `webview\`。完整迁移或灾难恢复应在软件完全退出后复制整个 `%LOCALAPPDATA%\GEOContentPlatform`。
- 恢复前先保留当前目录副本；不要在软件运行时直接替换 `geo.db`。

## 发布安全边界

真实发布不是一个可由环境变量随意切换的界面按钮，而是构建授权、运行时探针和单次任务确认共同组成的边界：

1. `safe` profile 强制保持 `ALLOW_REAL_PUBLISHING=false`，不打包 Playwright、Patchright、OpenCV 或发布所需的浏览器运行时；调度器也以 `allow_real=False` 启动。
2. `authorized_real` profile 会打包 Playwright/Patchright 驱动，但启动时仍先保持总闸门关闭。软件必须找到本机 Google Chrome，并让两个驱动各自打开一次纯本地离线页面；只有探针全部通过，当前进程才设置 `ALLOW_REAL_PUBLISHING=true`。桌面调度器本身始终以 `allow_real=False` 启动，不能无人值守访问真实平台。
3. 发布任务必须在创建时绑定明确的媒体账号。创建前会按渠道对正文和标题做预检，生成带安全缓冲的可编辑平台版本，并对**实际待发送**的标题和正文重算可引用性：字数等平台确定性规则不合规、门禁过期或存在 P0 风险项时，不得创建真实发布任务；总分低于 75 只显示黄色质量建议，不冒充平台硬限制。200/600/1000/1500 字常用档位分别采用精简、短、标准和长文适用项，发布副本仍按每个平台安全线自动压缩。控制台的“一键修复并重检”可修复标题、结构、长度和不兼容格式，但不会伪造数据、来源或客户案例；无法安全修复的 P0 项继续明确阻断。界面展示原稿字数、实际发送字数、平台上限、软件安全线与门禁问题；原稿保持不变，标题和正文都不得在发布器内静默截断。任务随后冻结实际发送的标题、正文、账号、素材和版本指纹；执行器领取后还会在加载发布器前核对该指纹。平台规则仍可能变化，预检通过不等于平台承诺接受或 AI 模型会采纳内容。
4. 平台需要扫码、短信验证码、滑块、人工确认或可能触发风控时，界面会在执行前提示，执行中再按平台真实响应转入待人工处理；软件不会绕过验证。媒体账号卡片旁展示的单日建议数量和间隔是本产品的保守运营参考，不是平台官方额度、不会阻止平台临时收紧规则，也不构成账号安全保证。账号限流、处罚或封禁风险由实际运营者承担。
5. 状态 `processing` 只表示发布器此刻正在调用平台；该状态不能重试，也不能人工核验，以免重复发送。只有调用已结束但平台没有返回可核验成功或失败证据的任务，才进入“已提交、待平台核验”。核验弹窗提供该平台内容管理页/创作者后台直达入口；操作员应先查作品、审核和草稿记录，再登记公开链接或核验结果。选择“未发布”前，必须确认发布/登录窗口和旧执行已经停止、至少等待 5 分钟并完成后台检查，之后才能把任务收口为失败并重新创建或重试。核验动作本身不会再次发送内容。
6. 对尚未建立任务的即时发布批次，操作员核对所选文章、平台、账号、素材和平台副本后只做一次批量强确认；软件随后创建每个平台的独立任务并按本机顺序连续执行。单项失败、需验证或待核验不阻塞后续任务，也不会自动重试该项。既有任务仍可单项确认或显式勾选后批次确认。真实定时任务到点后只进入队列，仍须人工确认；只有 Demo 定时任务可以自动演示且不会访问平台。
7. 旧版 `/postVideo`、`/postVideoBatch` 直接发布入口在桌面版始终关闭，避免绕过任务授权和状态机。
8. Bilibili 只开放视频兼容链路，不提供文章发布。`authorized_real` 启动时会在 EXE 外部查找本机 `biliup 1.2.4`，并同时核对可执行文件大小、固定 SHA-256 `5500912978355E7A64DBBE86EBD7ADE2CD4EC8BBC91E16998E4AEA7359D0FCDD` 和离线版本输出；三项全部一致才在该进程内开放登录与上传。登录、凭据读取和上传子进程均登记在桌面宿主管理的进程树中，正常结束、取消、超时、异常或退出软件时只清理本次登记的进程树。桌面版不会下载、更新、打包或执行未知版本，`safe` 始终关闭。该兼容链路只适合已有获授权运行时的内部受控使用；正式商用仍应优先申请 Bilibili 官方开放平台资质、应用和令牌，并完成平台与上游权利审查。

`authorized_real` 表示产品具备受控真实发布执行路径，不表示所有平台账号已经登录，也不表示平台页面在未来不会变化。媒体账号页会如实显示运行时与账号状态；缺少 Chrome、驱动或有效登录时，软件保持发布闸门关闭或要求人工处理。

## GEO 诊断与成本展示

GEO 诊断对项目定位、可发现性基础、竞品参照、内容资产就绪度和 AI 可见度基线做本机确定性评分，并输出证据、分级缺口、行动目标和复测口径。对临时内容诊断时，持久化记录只保存输入摘要，不保存临时标题和正文；对已保存项目和文章的诊断会把当前内容及可见度证据版本纳入摘要，使证据发生变化后能够形成新的可比基线。详细契约见 [GEO 诊断闭环与 AI 成本台账契约](./geo-diagnostic-cost-ledger.md)。

独立“成本账单”界面只汇总真实的模型操作：`generate`、`optimize`、确实调用模型的 `platform_adapt` 和每个成功取得回答的 `visibility_sample`。provider 不返回 usage 时标记为“未知”，有 Token 但没有经过核对的价格时标记为“未定价”，未知与未定价都不会填成 0，也不会混进已核算金额。金额按币种分别展示；单价通过 `AI_PRICE_CATALOG_JSON` 配置，并随每次调用保存快照；最终结算仍以供应商账单为准。平台账号登录、上传和发布不消耗模型 Token，不能为了展示成本而杜撰“发布 Token”。当前账单汇总会覆盖筛选条件内的全部匹配记录，但明细/CSV 是有上限的最新窗口；游标翻页、管理员价格目录、预算预警和供应商账单对账仍是 P1。

## 安装、升级、回滚与卸载

### 安装

把 EXE 和随附的 `GEO-Content-Platform.sha256.txt` 放在普通用户可读目录即可，不需要管理员安装。先打开 manifest 核对 `publishing_profile`：只有值为 `authorized_real` 的包才可能执行真实发布。该 profile 还要求本机安装 Google Chrome；Edge WebView2 只负责显示软件窗口，不能替代发布自动化所需的 Chrome。当前构建未做 Authenticode 代码签名，Windows 可能显示“未知发布者”或 SmartScreen 提示。只有在来源可信且 SHA-256 与交付清单完全一致时才继续；企业策略禁止未签名软件时，应改用后续签名构建。

### 升级

1. 退出工作区并关闭窗口，确认进程已经结束。
2. 点击“立即备份”，并在关闭后复制整个本机数据目录。
3. 校验新 EXE 的 SHA-256 和版本说明。
4. 用新 EXE 替换旧程序文件；不要覆盖 `%LOCALAPPDATA%\GEOContentPlatform`。
5. 启动新版本，检查登录、项目、可见度历史和健康状态。

数据库建表使用兼容式 `CREATE TABLE IF NOT EXISTS`，不会在正常升级中清空既有表；但这不替代升级前备份。

### 回滚

关闭当前版本后，换回已经验收且哈希已固定的 `safe` EXE，再用同一数据目录启动。`safe` 构建会重新强制关闭真实发布，不能靠残留环境变量解锁。AI 可见度历史和采样幂等表都是附加表，旧版本即使不读取也不会自动删除数据或重发请求。当前没有名为 `AI_VISIBILITY_ENABLED` 的运行时开关，不能把不存在的环境变量当作回滚手段。

### 卸载

关闭软件后删除 EXE 即可移除程序，本机数据仍会保留。只有在确认备份有效且确实不再需要项目、素材、账号会话和历史后，才删除 `%LOCALAPPDATA%\GEOContentPlatform`；删除该目录不可由软件恢复。

## 构建与验收

在 PowerShell 7 或更高版本的仓库根目录执行。脚本包含中文交付文件名，因此会拒绝 Windows PowerShell 5.1，避免旧版默认编码破坏路径。默认生成可回滚的安全版：

```powershell
.\scripts\build_windows_desktop.ps1
```

已经取得本次真实发布构建授权时，显式生成真实发布版：

```powershell
.\scripts\build_windows_desktop.ps1 -PublishingProfile authorized_real
```

构建流程会同步锁定的桌面依赖；未跳过测试时还会临时同步发布依赖，以运行脚本中列出的桌面/认证/可见度/发布闸门/健康回归和前端测试。`safe` 在进入 PyInstaller 前会再次精确同步并移除浏览器发布依赖，避免测试环境污染安全版；`authorized_real` 则保留这些依赖并由 spec 明确收集。流程还会执行 `npm ci`、构建 Vue，并在 GUID staging 目录打包单文件 EXE。成品随后从独立临时工作目录完成两次验收：HTTP 健康与首次认证状态，以及隐藏 Edge WebView2 中的首次设密、创建合成项目、本地可见度分析、历史留存和原生备份。`authorized_real` 还会把 `PLAYWRIGHT_BROWSERS_PATH` 指向空缓存，再使用系统 Chrome 完成 Playwright 与 Patchright 的纯本地页面探针，证明 EXE 没有偷用构建机已下载的浏览器。全部通过后，staging 才会整体提升为不可覆盖的版本目录；验收不会访问发布平台或发送真实内容。

产物目录形如：

- `release\windows\GEO-Content-Platform-1.2.8-<safe或authorized-real>-<UTC时间>-<提交短SHA>\GEO-Content-Platform.exe`
- 同目录的 ZIP、`GEO-Content-Platform.sha256.txt`、`GEO-Content-Platform.manifest.json`、`build-info.json`、`首次使用.md`、`AI可见度接口契约.md`、`GEO诊断与成本台账.md`、`Windows桌面技术说明.md`、`LICENSE.txt` 和 `THIRD-PARTY-NOTICES.txt`

只有在同一提交上已经独立跑完回归时，才可显式使用 `-SkipTests`；manifest 会如实记录该状态。该参数仍不会跳过两个成品 EXE 冒烟测试。默认拒绝脏工作树，构建成功也不等于完成代码签名；签名状态会写入 manifest，外部商业交付仍必须单独完成签名与许可门禁。

## 故障定位

支持人员可以在隔离目录中运行成品健康检查，不触碰用户数据库：

```powershell
$geoCheckDir = Join-Path $env:TEMP "geo-desktop-health"
.\GEO-Content-Platform.exe --health-check --data-dir $geoCheckDir --health-report (Join-Path $geoCheckDir "health.json")
Get-Content -Raw (Join-Path $geoCheckDir "health.json")
```

优先排查：

- 提示“已在运行”：切换到现有窗口；不要反复启动相同数据目录。
- 空白窗口或 WebView 初始化失败：确认 Microsoft Edge WebView2 Runtime 可用。
- `authorized_real` 显示发布运行时不可用：确认 Google Chrome 已安装在当前用户或系统标准目录；Chrome 与 Edge WebView2 是两个独立前提。
- 平台账号要求登录：在媒体账号页点击“添加 / 登录”或“重新登录”，然后在软件弹出的浏览器、二维码或终端窗口中完成平台验证。
- Bilibili 显示不可用：确认本机外部兼容运行时位于默认用户目录、版本和 SHA-256 均与交付清单一致；软件不会自动下载或信任其他二进制。若用于对外商业服务，请改走官方开放平台接入评审。
- 启动失败：查看 `%LOCALAPPDATA%\GEOContentPlatform\logs\desktop.log`。
- 无法登录：确认键盘布局、大小写和首尾空格；连续失败可能触发临时频率限制。
- “本地认证配置不可用”：保留 `config\auth.json` 和整个数据目录的副本，不要直接编辑 JSON；交给维护人员核验。
- 可见度没有命中品牌：核对项目主名、产品名、别名和回答原文；短词、模糊命中与歧义会降低置信度或要求人工复核。
- 引用数量为零：当前引擎只识别回答原文中显式出现的 `http://`、`https://` 或 `www.` 地址，不会联网推断来源。
- 真实采样按钮不可用或请求被拒绝：先在系统设置核对统一 AI 的 HTTPS 服务地址、精确模型 ID 和“凭据已保护”状态，再核对 prompt、1–5 次采样数量和外发确认。不要把缺失凭据改写为“已测试”；无完整配置时软件不会调用模型。
- AI 服务偶发 HTTP 404：这通常是 Base URL 路径或模型/接入点 ID 不匹配，不是源码文件正在修改。Ark 应以 `/api/v3` 为基址，千问兼容模式应以 `/compatible-mode/v1` 为基址，DeepSeek 官方根地址会直接解析到 `/chat/completions`；软件只补一次该后缀，完整端点不重复追加，并在 400/404 回执中显示经过脱敏的实际请求地址。
- 真实采样超时或显示“需要人工处理”：先核对供应商账单和原请求 ID/幂等键；同键只回放已有结果，软件不会自动重发。只有确认确实需要新调用后，才由操作员建立新的请求。

## 外部引擎与扩展采样边界

同事的纯分析算法已经以本机 Python 版本接入 AI 可见度，操作员确认的当前配置模型顺序采样也已接入；但这不代表已经具备 provider 网页自动登录、定时/无人值守/分布式采样，也不代表同事内容生成服务已经上线。内容生成适配层仍要求版本化 `POST /api/v1/generate`、健康检查、受限内部地址、独立 Token、超时和响应大小限制；在实际地址、Token、镜像摘要、许可和数据发送边界完成验收前，应保持现有内容引擎设置，不发送真实客户或项目数据。

发布后分析标识为 `ai-visibility-python-port-1.1.0`，发布前内容编译标识为 `geo-article-compiler-2.3.0`，可引用性门禁标识为 `ai-citeability-rules-2.2.0`，长度档标识为 `target-length-score-profile-1.0.0`，临时统计标识为 `metrics-ad-hoc-python-1.1.0`。200/600 字短稿与 1000/1500 字长稿使用不同的适用项，但短稿不会自动加分，缺证据和风险边界仍会真实扣分；缺少目标长度的旧记录保留旧口径。这些结果不能与 provider grounding 运行或历史 TypeScript 指标直接拼接；详细迁移和权利阻塞见 AI 可见度接口契约与 GEO 算法融合说明。内容结构门禁只能提升被准确提取和引用的准备度，豆包、千问、DeepSeek 等模型是否实际采用仍须用固定问题、失败分母和至少 14–30 天同口径回测验证，不能由单次短测外推。
