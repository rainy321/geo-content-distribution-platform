# Windows 桌面软件

桌面程序名为“GEO AI 搜索工作台”，启动文件为 `GEO_AI_Workbench.exe`。使用独立 WebView2 窗口，包含 Python 后端和已构建的界面。需要 Windows x64、Microsoft WebView2 和可用的 Chrome 或 Edge。

本文对应 **2026.10.28.1 反馈驱动内容迭代版**。加入客户录入外部回答、提问条件追加、业务资料核对历史、下一步导航和官网公开内容检测。后续反馈参与新的AI策划，已确认事实继续作为文章事实来源。保留公司资料维护、Bing指引及原窗口自适应修复。功能范围以实际构建、原生界面和数据保留验证为准。

客户可在反馈区复制原题、粘贴手机或同事取得的回答，选择明确掌握的条件；未知项留空，不伪造成软件原生采集。条件和业务材料核对均追加到同一原文，保留旧意见。摘录须精确来自原文，并对照本轮已确认事实；识别业务资料不等于事实正确、交付能力或GEO成功。

未提交草稿和未确认保存的冻结请求只存于本次应用会话的有限内存，跨步骤或页面可以继续，关闭软件前应保存或导出。不会把客户原文写入浏览器长期存储；容量不足时明确提示且不淘汰未确认记录。保存中按组件分别锁定操作，迟到回执不会串入其他项目；未知回执按同一输入检查，不自动另建反馈。

AI策划最多选择6条后续代表记录，先保留最新外部反馈，再按来源与界面取代表，不按回答正负挑选；截断会明确说明。选题保留反馈编号与原文摘要指纹，写作时不把这些回答或署名意见当作事实。原始问题的有效性限制仍适用。新反馈或核对意见在生成期间变化时，旧AI结果不会覆盖当前资料；旧稿仍在内容库，不能仅凭重用的选题编号把旧编辑写入新稿。

官网检测只读取本轮已经登记的1到5个公网HTTPS页面，记录服务端HTML、名称文字、标题、描述、canonical、noindex及有限JSON-LD观察；不运行网页脚本、不跟随新发现链接、不修改网站或自动提交搜索。单次历史即使因资料版本变化而不属于当前范围，也可单独查看。HTTP、名称文字、索引与AI采用分别记录，近名或名称后接中文句子的字面包含需结合上下文核对。

模式选项指定本次测试要求，网页的实际模式仍需核对。个人账号也可以进入豆包工作，换账号不是切换普通模式的保证；模式不一致时发送前暂停，恢复入口提示检查官方页面，不再一律要求重新登录。普通对话与工作任务分别记录。任务历史默认显示最近5条，展开后每页20条；旧任务及查看入口保留。

来源观察分别提示官网域名匹配、完整公司名标题、已确认的关联公司、标题中的其他公司和待核对项。短别名或同音字不自动合并为一个主体；产品的运营公司工商条目也不等于找到了产品。域名和标题只说明来源范围，不证明业务、案例或实际交付能力。其他主体的页面仍可用于行业和渠道调研，不能成为本公司的事实资料。既有来源在读取时补充提示，原报告和事实资料保持不变。

正常点击后观察到水滴公司页面时，仅在完整公司名、唯一一级标题、发布方及固定公司页地址都一致，且两处标题仅有特定破折号差异时，允许保留真实链接并记录核验方式。登录页、认领页、其他主体或不足以确认的页面继续保持未知；这不等于增加官网引用，也不回写旧回答证据。

回答明确自称以用户既往个人记录为本次作答依据时，保留原文并按来源声明隔离，不计入公开 GEO 有效题分母、曝光和业务识别比较，也不将这类摘录作为来源驱动文章的依据。强个人记录来源声明在工作模式、普通对话及模式未知时均适用；一般企业内部资料的既有判断仍限定工作模式。该判断识别回答中的说法，并不证明平台实际读取过用户资料。否定、假设、未来动作和一般产品能力描述仍需区分，不能只因出现“个人记录”等词语就排除。

公司资料服务独立于文章发布。公司档案可在来源线索或反馈区进入企查查资料维护，分别准备官网和企业简介任务。产品档案显示不适用，不能把产品名套入公司补正。软件使用已有品牌资料与已核对的公开事实准备文字，保存前需核对公司主体、模块和公开内容；不会把客户案例、资质或工商登记变化补写成事实。

打开任务时沿用正常的企查查专用浏览器会话，按当前页面提示处理登录、缺姓名或联系方式、验证码及拼图验证。姓名、联系方式和验证由用户在官方页面处理，私人输入留在浏览器，不作为公开文案或日志保存。软件辅助填写和核对公开资料，最终确认提交由用户本人在平台完成；记录结果时只读检查同一份申请，不代点最终确认或自动重复提交。页面若出现收费或权限差异，按提示暂停。

官网与简介分别保存任务和处理状态，软件重启后恢复任务列表；重新打开时核对平台当前页面，不凭旧缓存假定仍已登录或原填写内容仍在。专用窗口运行期间，其他桌面自动任务按软件状态等待；处理结束后按提示关闭窗口再继续。提交结果无法确认时保留未知，不能重复点击取得确定结果。待审核、需要补件、公开资料已更新与搜索已采用分别判断；资料维护不会增加文章发布数、收录数或AI采用成功数。软件外研究回执属于外部历史记录，不能作为本版原生新提交的验收证明。

Bing 官网接入由网站负责人在日常普通浏览器中打开官方站长后台，正常登录、添加官网，并下载平台实际提供的 XML 验证文件。软件提供步骤说明，保存用户选择的原文件，并生成对应官网的部署说明；文件仍需网站负责人部署到官网，上传到软件不等于部署完成。登录提供方若拒绝受控浏览器，交由用户在日常普通浏览器手动处理，不伪装自动化、不迁移 cookies 或 OAuth 信息，也不接收账号密码。

软件按当前官网地址核对公网验证文件是否与上传原件一致，并检查站点地图是否可访问。公网核对通过只证明文件部署和本次访问结果；仍需负责人在 Bing 点击验证，看到验证成功并进入网站控制台后，再保存“用户确认”的结果。软件不会把公网 HTTP 检查当作 Bing 后台验证，也不代登录、部署文件或点击后台提交。

负责人可按说明在 Bing 提交一次站点地图，并在软件中分别记录后台实际显示的处理状态和逐页 URL Inspection 索引结果。收到提交提示后，列表仍为 Processing 时，应记录“正在处理”，不重复提交；发现网址数为零、最后抓取时间空白或索引结果未确认时，均保留实际值或未知。站点地图可访问、已提交、处理成功、页面可抓取、明确已索引与豆包采用是不同结果，不能互相替代。站长后台结果标注为用户确认，不伪装成软件直接读取后台的证据。

官网接入进度保存在本机，可关闭软件后继续；公网检查与人工确认分别保留时间和状态。记录该进度不会增加文章发布数或 GEO 成效计数，也不保证搜索收录或豆包采用，不能据此断言 Bing 是豆包的搜索来源。

既有知乎路径继续支持以空行分隔的普通段落、`#` / `##` 标题、HTTP(S) 链接和简单表格，通过平台正常的 Markdown 文档导入处理正文，再按段落顺序、标题层级、链接文字及网址、表格单元格做语义回读，并单独核对文章标题。图片、代码、列表等尚未支持核对的结构，以及读回不一致的内容，均暂停并提示审核，不静默删减或当作已就绪。现有正文不会被自动覆盖，导入状态未确认时不重复导入。候选源码的导入检查不等于新稿已公开，也不能证明 GEO 提升；实际交付结果以最终构建和对应清单为准。

同题单题复测继续支持：从已保存的原报告选择一道问题，沿用原问题文字单独观察，并保留前后回答、可见来源与采集时间。原题未提供网址时，复测也不额外添加官网或提示答案；已发送、状态未知与等待正常验证的请求继续按原提交证据处理，不通过重复发送取得结果。单题观察与原多题报告分别保存，未选问题不算失败或零曝光，原报告与原问题保留。它与“继续未发送问题”不同：后者只恢复原任务未发送的部分。

前后对照需核对题目、界面模式与模型等条件。原回答无效、条件变化或证据缺失时，应标明比较限制，不把未知当作下降或提升。分别观察名称提及、官网地址文字出现、公开业务资料是否被采用以及可核对的引用网址。回答可能提到备案域名，却仍未识别公开业务资料；地址文字出现不等于官网被引用、业务正确或优化成功。单题变化不代表自然选型推荐已改善，也不能单凭一次前后变化归因为某次发文或网站修改。候选功能实际交付以最终原生界面、数据保留验证和对应发行清单为准。

用户提供的外部回答单独标为“用户外部反馈”，保留原文和摘要校验值，不伪装为软件原生采集。关联原题只用于归档；未提供实际题文、界面模式或模型时，对应条件保持未知，不能当作严格同题对照。外部原文中可观察到官网地址文字，也不能据此补造来源链接、完整性证明或原采集证据。

后续补充的实际提问、新建会话和首条提问声明，保存在同一外部答复的条件历史中；不新增一条回答，不替换原文，不改变完整性、模型、采集时间或原报告统计。界面标注为用户声明，不能冒充软件独立核验。只有界面或模型未知，不会把已确认的外部负向业务观察丢弃。

公开业务资料采用情况默认待核对。人工或助手核对需标明核对方，使用回答原文的精确摘录，并关联本轮已确认的事实资料；可记录已识别、未识别或未知。该结论只说明所提供回答是否采用相关公开资料，不是自动事实正确率，也不证明公司具备或缺少实际交付能力、客户案例或项目经验。未完成或被排除的回答保留未知，不作为业务未识别或零结果。

未显式指定浏览器时，先选择本机已安装的 Chrome；未找到 Chrome 时再选择 Edge。明确指定的浏览器配置继续优先，不需要客户为默认选择手动配置环境变量，不会迁移或合并不同浏览器的用户目录。

本次本机排查中，默认 Edge 在启动阶段退出，未完成原生检查；显式使用本机 Chrome 的完整原生检查通过。这是本机运行观察，不表示其他 Edge 安装均有相同问题；本版最终程序与浏览器验收结果以对应发行清单为准。

知乎发文沿用有效的本机登录会话；已确认登录后继续检查编辑器、正文和创作声明，仅在平台实际要求时处理登录或验证。发布前读取编辑器中的标题与正文并核对，空白、截断或不一致时停止，输入字数和写入日志不作为正文已就绪的证明。创作声明区域在有限等待后仍未就绪，或控件、选项和选择结果缺失、存在歧义或不一致时，按实际阶段提示处理，尚未点击发布；这些情况不一概判为登录失败。已登录、正文就绪、声明确认和公开发布分别核对，未确认的原任务仍保留。知乎登录和真实 AI 发文使用可见的普通本机浏览器；只读检查使用独立浏览器会话。

历史报告中标记为 `browser_error:TimeoutError` 的任务，在后台明确确认原计划和原报告仍有可恢复的未发送问题时，会显示“继续未发送问题”入口。续采只处理获准范围内的未发送问题，保留已完成结果；已发送或提交状态未知的问题不会自动重发。旧超时记录可显示入口不表示已经完成真实续采、同题复测或取得 GEO 提升，后续结果仍以原任务实际记录为准。

以下采集与反馈保护继续保留。豆包整页显示“该页面暂时不可用”时明确说明网站故障；任务中断不再显示采集完成，并根据证据区分尚未发送、已尝试发送和状态未知。连续多题的发送状态独立保存。长段写作资料等待输入稳定、两次逐字核对，再核对明确的发送按钮，保存尝试证据后只点击一次；不会在点击后再回退为回车发送，也不会把执行发送操作等同于收到回执。AI 分析区分回答中的说法和核实事实，构造的测试场景不作为真实客户需求，草稿仅使用已确认的写作事实。反馈页显示每轮有效、失败、待测与内部资料隔离题数；没有有效回答时不显示曝光比较，也不把该尝试标成反馈完成。旧报告缺少阶段或发送证据时保留未知，不回写原文件。正常验证原地等待、内部资料隔离、统一排期额度、稿件与任务确认摘要、原任务重排及普通本机浏览器保护继续保留。准确检查结果、软件哈希及源码提交以对应 Release 清单为准。

对接发布 API 时，真实模式的 `POST /api/publish` 需携带文章列表或详情返回的 `review_fingerprint`，字段名为 `expected_review_fingerprint`；`POST /api/publish/jobs/<id>/execute-real` 需携带任务详情返回的 `confirmation_snapshot`，字段名为 `expected_confirmation_snapshot`，并保留 `confirm: true`。缺失摘要返回 400，摘要过期返回 409；应重新读取并由用户核对，不能自动重试。摘要用于识别过期页面，原有审稿、账号、额度与授权检查仍须通过。演示模式维持原有调用方式。

小红书图文入口使用标准 Playwright。终端二维码解码或字符渲染模块缺失时，仍可在浏览器或已保存的二维码图片中正常扫码，不影响模块加载；浏览器实际启动和正常登录结果需分别核对。

软件可分别建立公司与产品档案，填写当前对象别名、运营公司与额外官方页面。公司提及不会自动计入旗下产品；同域不同产品路径分别匹配，主网址和额外官方页面不自动扩展到整站或其他子域。此次按更新后的官网分别测试北京同于野科技有限公司、懂AI中转站、同于野软件，详见[测试方法与配置](geo-search-testing.md)。这些工作模式测试与普通对话基线分别保存；公司回答中声称使用账号内部资料的一题已排除公开曝光统计。账号登录成功仍可能进入工作界面，普通对话基线需要实际可用的普通对话入口，不能用工作模式结果代替。

普通对话与工作模式使用独立浏览器会话，原工作会话保留，不复制企业连接器。普通对话首次使用需要正常登录。明确声称使用内部企业或飞书资料的工作模式回答保留原文，但不计有效题和公开曝光，也不把内部摘录及来源传给文章生成。旧报告、任务和工作区读取时应用同一排除规则，不改写原始采集文件。来源标题可接受完整文字的全半角等价，保留原始标题与匹配方法；不以近似标题或猜测网址补充来源。

公司名、产品名和明确别名以客户档案与已核对事实为准。新出题、选题和写稿提示要求逐字保留名称，避免把域名拼音或自动会话标题改写成品牌名称；生成稿仍需核对名称与事实。

默认首页为“开始优化”，按品牌、搜索基线、内容、发布、反馈五步推进。输入品牌名称、官网和一句话业务介绍即可开始；运营公司、目标客户与模型设置可展开补充。原来的采集报告、内容任务单、内容库和发布中心仍可从侧栏打开，管理配置收在“管理工具”。界面有短时淡入和位移动效，并尊重系统减少动态效果设置。

已有内容不依赖本机进度缓存才能找回。在“搜索基线”步骤的“继续已有内容”中选择该对象的原报告与稿件，点击继续后整体恢复同一轮基线、分析和文章，不另建任务。多个周期明确选择；同名项目按对象类型与完整网址区分。切换周期时保留未保存编辑的本机副本。

| 步骤 | 用户操作与得到的结果 |
| --- | --- |
| 1 品牌 | 填写公司、品牌或产品资料，选择自己的项目；资料按品牌保存。 |
| 2 搜索基线 | AI 按业务提出问题，用户预览确认后采集回答、可见来源与时间。自然选型、点名核验和官网引导核验分别展示。 |
| 3 内容 | 根据有效问题与实际来源制定选题，核对事实，选择通用渠道或已接入目标，生成并编辑平台稿。 |
| 4 发布 | 审稿就绪后选择已具备能力的内置发布器，或打开已配置目标辅助填写；官网稿可导出。提交和公开结果分别记录。 |
| 5 反馈 | 查看文章、发布证据与原基线的关联，按原计划开展新的同题复测，保留失败、未知和条件差异。 |

先在“来源与平台用途”核对使用方式。新平台和未核对的旧配置默认仅研究，保留原稿、导出与审核记录；不会直接要求登录、实名或发稿。选择投稿或商业用途后，需登记运营方对该栏目的规则核对；固定栏目限制仍由软件检查，勾选不能覆盖。这个记录不是平台许可或自动核验。平台用途、规则网址或入口改变后应重新核对。

用途可继续时，再查看“平台接入准备”，备好正常登录方式，并按实际平台提示完成安全验证、实名或微信、手机号绑定。在专用窗口操作后保持原窗口打开，返回软件点击“检查并继续”；软件沿用同一任务和账号会话，在一个可复用的检查标签核对编辑入口，检查期间保留原登录、验证或绑定页面。关窗不能证明已登录或会话已保存；需要处理的要求会继续显示，已写入后的按钮为“检查当前窗口”，只读检查，不重新填写。

CSDN 专用辅助填写无需配置 CSS 选择器；仅确认空白或完整匹配已知欢迎示例后，才会通过平台正常 Markdown 导入新建文档，原文档保留，其他已有标题、草稿或未知示例会暂停处理。导入后逐字核对标题、全文及内部换行，不一致时不会再次导入。发布前需核对平台已有标签、AI 创作声明及可见范围；自定义标签可能受账号等级限制，跨站备份或同步由用户选择。最终提交由用户完成，填入不计为已发布。这些准备状态和同任务复检仅在实际包含新版界面及 `check_destination_session(task_id)` 原生接口的桌面构建中可用；旧版需按提示升级，可用版本以对应 Release 清单为准。

“平台结果核对”可逐篇登记待审核、审核未通过、公开可查看或暂不确定，并记录平台原因。这些是运营方观察，软件不自动替代平台审核或公开页面核验。待审、拒绝的文章不能再登记为公开发布；旧提交记录会保留，但暂不进入发布后效果统计。“暂不确定”和提交成功提示不能清除已有保护；只有重新核对具体公开链接、标题与全文后，才能记录对应当前稿件的公开观察。保存结果不会重新投稿。

写作会话初始使用本轮基线的豆包界面和请求模型选项，明确修改后的选择按任务单保留。切换任务单或刷新时不会把另一个任务单的选择、延迟结果带进来；实际模型仍以平台当前显示为准。

内容步骤顶部的“豆包写作会话”可选择豆包对话或豆包工作，并直接打开对应登录窗口；模型选项和详细登录说明可展开。已有报告的搜索基线页也保留登录入口。反馈页的登录入口使用原基线的复测会话，与当前写作选项分开。

登录失效、安全验证等待结束、界面不匹配等已知情况会显示中文处理卡；内部原因码放在任务详情中。登录操作与生成操作分别记录，重新登录不会自动生成文章，也不自动重发旧问题。只有证据明确显示未尝试且未提交，才说明“问题尚未发送”；已发送或发送状态未知时，重新开始前须核对原会话。桌面的“新测一轮”会再次提问，不等于 CLI 的只续未提交问题。

网页的历史 `from_logout` 参数本身不能证明当前仍未登录；需要结合当前登录/验证提示、实际界面及可用编辑器判断。真实退出页、未知页面或提交身份无法确认时继续暂停。正常登录解除后，已尝试的问题仍沿用原提交证据，不因页面恢复而再次发送。

测试页重开时，匹配同一对象的终态计划和报告不会被本机空缓存盖掉，用户明确选择的报告优先。后台已结束不代表报告全部成功，报告自身的停止原因和未完成题仍保留。内容明细页更新同一轮平台配置或刷新时保留未保存的事实输入；其他页面改动了已保存事实时，要求重新核对后保存。

腾讯云开发者社区接入前应核对实名认证、手机验证、首次专栏审核及封面要求，编辑器可能自动保存草稿。[社区规范](https://cloud.tencent.com/developer/article/1006434)不鼓励较多段落为 AI 生成的内容，并限制推广引流；标注 AI 或仅做 AI 审校不能据此认定允许发文。账号前提和编辑流程参见[发表文章文档](https://cloud.tencent.com/document/product/1212/42695)，最终按当前账号页面核对。该接入起点不表示已完成自动投稿适配。

软件内可以选择客户资料、通过 AI API 或已登录豆包生成固定问题、预览确认后启动串行测试、停止任务及查看完整报告。首次使用豆包采集时点击“登录豆包”，在专用窗口正常登录/验证，完成后关闭专用登录窗口。主流程显示这次操作的“上次登录检查”摘要，直到开始新任务或切换对象；摘要显示所选与最后观察到的实际界面、登录及验证提示，关闭窗口本身不能证明登录成功或会话已保存。所选与实际不一致时先核对界面选项，采集前仍会检查并拦截错配。采集中出现验证时应保持采集窗口打开，软件等待同一条请求，不自动重发。选择与你实际账号对应的“豆包对话”或“豆包工作”；模型选项只选择正常可用项目。没有选择品牌项目时，豆包出题可以使用当前报告对应的客户资料。

报告上的“用本报告制定内容任务”和侧栏“采集驱动内容”连接后续选题、写作事实、平台稿、内容库审稿、发布链接和同题复测。生成稿先保存为草稿；写作来源与曝光采集分开记录。详见[采集到发布说明](geo-content-loop.md)。

“用豆包生成问题”完成后，在问题列表检查客户业务与问题，再点击“开始测试”。界面显示任务状态；逐题采集、固定计划、失败排除、模型记录和重复提交保护复用现有执行器。遇到登录和安全验证时在专用窗口正常处理，软件不绕过验证。停止或关闭软件会取消未完成任务，提交状态不明确的运行标记为待检查，不自动重发。

当前曝光采集只接豆包网页版，平台、界面和实际模型在报告中记录。已选模型与要求一致时复核当前标签；未知或不一致时仍须选择正常可用选项。研究、出题和写稿的长资料会做发送前原文核对及发送后提交证据确认；这类内容编辑请求不计入曝光统计。

2026.10.20 五步流程版的真实验收记录如下；它早于本版对象拆分，不能作为三个新对象的搜索结果：

| 环节 | 已确认的进度与边界 |
| --- | --- |
| 自动出题与基线 | 完成一次干净的自动出题和三题采集，三题均取得有效完整回答。样本很小，不能推断总体曝光。 |

## 从采集到 GEO 行动

2026.10.29.3 在内容步骤中展示本轮 GEO 行动方案：每项行动关联已固定的原题，说明要补的缺口、改动方向、事实依据、已观察到的来源路线，以及复测时应核对的回答内容。自然需求发现、品牌与业务识别、官网资料采用分别安排，品牌核验改善不会代替自然推荐结果。问题安排数只表示有几道原题已有行动，不是命中率或优化成功率。

新策划可保存缺口与具体改法；旧选题只读派生行动提示，不回写旧记录。选定行动只切换当前写作选题，生成仍由用户发起。行动要求进入 AI 写作资料，新稿保留当时的行动方案和原题验收要求；采集回答与行动假设不进入已确认事实库。发布后继续按原题复测并登记实际前后变化。

uv venv .tmp/desktop-build-venv --python .venv/Scripts/python.exe
uv pip install --python .tmp/desktop-build-venv/Scripts/python.exe ".[desktop]" playwright==1.52.0 pyinstaller==6.22.3

./scripts/build_desktop.ps1 -Mode onedir

安装使用 `dist/desktop-onedir/GEO_AI_Workbench/` 整个目录，入口为其中的 `GEO_AI_Workbench.exe`，同级 `_internal` 必须一起保留。采集依赖随程序固定安装，并在打开窗口前加载。可选单文件构建仍支持 `-Mode onefile`，安装脚本使用目录版。打包只收集源代码、库、图标和前端构建；用户数据通过本机安装步骤导入。

构建后先用独立的空数据目录运行 `GEO_AI_Workbench.exe --data-dir <测试数据目录> --smoke-test`，核对实际五步窗口、原生桥接、旧报告空状态和正常退出。该检查只证明本地程序可运行，不证明外站已发布或优化有效。确认后可用 `./scripts/install_desktop.ps1 -Launch` 安装到本机；安装脚本会导入该用户已有的工作区资料，与纯发行包验证分开。

正式交付须重新构建最终源码和前端，记录源码提交、完整目录包及文件摘要，检查 ZIP 完整性，并排除数据库、报告、会话、日志与密钥。最后的 Release 说明应列出实际通过、未完成和需要人工处理的环节。历史冒烟测试不能替代新构建的验收。
