# GEO 桌面版首次使用

## 先确认这是什么版本

当前交付是 Windows 本机单用户便携软件。它把界面、业务服务和本地数据库装在一个 EXE 的运行边界内；不连接正式服务器数据库，也不会在后台、定时或无人值守取得外部 AI 回答。操作员可以在 AI 可见度页逐次确认一次受控模型采样。桌面包分为两个不可互换的构建 profile：`safe` 不执行真实平台发布；`authorized_real` 在本机发布运行时探针通过后，提供受控的媒体账号登录和真实发布流程。正式网站、网页部署和服务器迁移不属于本桌面交付。

由于同事交接 ZIP 未附 `LICENSE`/`NOTICE`，当前包含移植算法的构建限定为内部受控 Beta。取得书面内部授权或补齐可核验的权利声明前，不应把它转发给外部客户或作为已授权商业分发版本。

## 1. 校验并启动

交付包应至少包含：

- `GEO-Content-Platform.exe`
- `GEO-Content-Platform.sha256.txt`
- `GEO-Content-Platform.manifest.json`
- `THIRD-PARTY-NOTICES.txt`

在 EXE 所在目录打开 PowerShell：

```powershell
Get-FileHash -LiteralPath .\GEO-Content-Platform.exe -Algorithm SHA256
Get-Content -Raw .\GEO-Content-Platform.sha256.txt
```

两处 SHA-256 必须完全一致，并检查 manifest 的 `publishing_profile`：`safe` 是禁止真实发布的回滚版，只有 `authorized_real` 才包含真实发布运行面。当前构建未做 Authenticode 代码签名，因此 Windows 可能显示“未知发布者”或 SmartScreen 提示。不要仅因为文件名相同就运行；先确认文件来自可信交付渠道且哈希一致。企业设备禁止未签名程序时，请等待签名版本。

`authorized_real` 还要求本机安装 Google Chrome。软件窗口使用 Edge WebView2，但发布自动化当前明确依赖 Chrome；只有 Edge 或 WebView2 不能让真实发布运行时通过。

校验后双击 EXE。首次解包和 WebView2 初始化可能比后续启动慢；同一数据目录只能打开一个窗口实例。

## 2. 设置管理员口令

首次启动会显示“设置管理员口令”：

- 12–15 个字符时，需在大小写字母、数字、符号等类别中至少满足三类。
- 16 个字符以上可使用中文或英文口令短语。
- 不能使用首尾空格、控制字符或只有极少数重复字符的口令。
- 两次输入必须一致。

口令只在本机校验。软件把随机盐和 600,000 次 PBKDF2-HMAC-SHA256 的摘要写入 `config\auth.json`，不保存可以找回的明文。请使用密码管理器保存；当前版本没有“忘记密码”找回流程。

登录会话默认有效 12 小时。关闭窗口不应替代主动退出，尤其是在共用 Windows 账户的设备上。

## 3. 建立第一个品牌项目

进入左侧“品牌项目”，建立品牌底稿。AI 可见度至少依赖以下信息：

1. 品牌名称：所有样本的主分析实体。
2. 产品名称：会作为品牌别名参与识别。
3. 官网：用于判断显式 URL 是否属于自有来源。
4. 竞品：作为本项目的默认对比实体。

行业、描述和关键词可继续服务于内容创作与 GEO 优化。项目底稿应使用真实、稳定的命名；过短的品牌词容易产生歧义，分析时需要结合证据片段人工判断。

## 4. 完成一次 AI 可见度分析

进入“AI 可见度”后，可选择手工导入或受控真实采样；两种入口最终都使用同一个本机确定性分析器。

### 手工导入回答

按顺序操作：

1. 选择品牌项目。
2. 填写一个明确的监测问题，例如“适合中小企业的 GEO 内容工具有哪些？”。
3. 按需补充品牌别名和本批次竞品；这些覆盖项不会反写项目底稿。
4. 把已经从外部渠道取得的完整回答粘贴到“AI 回答样本”。
5. 多条回答之间用单独一行 `---` 分隔；每段完整回答计为一个样本，单次最多 20 条。
6. `回答来源` 和 `模型标识` 可以填写“千问网页”“qwen-plus”等标签，也可以留空。它们只用于溯源，不会触发连接或调用。
7. 决定是否勾选“保存到本机分析历史”，然后点击“开始本地分析”。

这一流程只分析用户已经粘贴的文本，不把问题、项目资料或回答发送给任何模型。

### 受控真实采样

要直接取得当前模型回答，展开真实采样区并按顺序操作：

1. 选择千问、DeepSeek、豆包或自定义兼容服务预设，并核对 HTTPS 服务地址和精确模型 ID；预设只是可编辑起点，以实际账号控制台为准。
2. 在当前软件会话填写 API Key，选择 1–5 次采样。密钥不会保存到项目或分析历史；切换 provider 或离开该页会清除该采样表单中的密钥。
3. 阅读调用前预览。每次外发的唯一自然语言内容是输入框中的 `prompt`；项目名称、产品、介绍、官网、文章、别名、竞品、媒体账号、Cookie、凭据和发布任务都不会发送给模型。服务地址、模型 ID、该 AI 服务自身的鉴权头和生成参数仅用于传输。
4. 勾选确认后才可执行。软件按顺序调用，最多 5 次，不并发、不定时、不在后台继续；任意一次失败、限流、超时或响应异常都会停止后续样本并保留已完成结果。
5. 查看结果中的请求 ID、幂等键、已完成/未执行数量、逐次回答、Token/费用凭据和失败原因。相同幂等键只回放原结果；中断或结果不明确时软件不会自动重试，先核对供应商账单，再决定是否由操作员新建请求。
6. 如需在手工区继续核对证据，可把本次回答导入手工分析；软件支持撤销本次导入。

请求级配置缺少服务地址、模型 ID 或 API Key 时会在联网前拒绝；完全不填写请求级配置时，也只有本机已配置完整 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` 才能执行。没有完整凭据就不会调用 provider。采样未请求网页搜索或引用核验，不能把回答中的时效性事实和链接视为已经联网验证。

“AI 内容创作”仍是独立的外部模型链路，应按其配置、费用和数据边界单独判断。

### 如何阅读结果

- 品牌提及率：包含目标品牌有效提及的样本比例。
- 声量份额（SOV）：品牌和竞品的有效提及按推荐位置加权后的相对份额；未进入明确推荐序列的有效提及使用固定权重。
- 平均推荐位次：只统计能够从编号或项目符号推荐列表识别出的位次；“未进入”不等同于完全没提及。
- 引用与自有引用：只计算回答原文中显式出现的 URL；不会联网打开页面、跟随跳转或猜测来源。
- 置信等级：综合样本量、结果稳定度和解析置信度。少于 5 条时不提供稳定的 95% 区间，单一样本只能用于核对规则命中。
- 可执行建议：至少需要 2 个有效样本，并由可追溯规则和样本证据触发；不是外部模型生成的结论。

展开“逐样本证据”可以核对命中的文字、别名、竞品、推荐位置和引用。模糊或低置信命中必须人工复核，不能只看汇总百分比。

### 本机历史

勾选保存后，系统会在 `data\geo.db` 中保存问题、回答原文、别名/竞品覆盖项、完整结果、算法版本和 UTC 时间。页面显示当前项目最近 10 次摘要，点击可恢复完整证据；后端最多允许一次读取 100 条摘要。

不勾选时，本次结果不会写入可见度历史。结果仍会在请求处理和当前页面内短暂存在，离开或刷新后不保证恢复。

### GEO 诊断、优化与成本

AI 可见度页还提供项目或内容诊断。诊断在本机按产品定位、可发现性基础、竞品参照、内容资产就绪度和 AI 可见度基线五个维度建立分数与等级，并给出 P0/P1/P2 缺口、行动目标和复测口径。已融合的同事算法范围包括品牌/别名提及、推荐排名、显式 URL 引用与来源分类、情感/属性、声量、置信度和证据驱动建议；操作员受控的当前配置模型顺序采样也已接入。尚未接入的是定时/无人值守/分布式采样，以及缺少正式地址、令牌或镜像的远程内容引擎。诊断用于把“优化前—采取动作—同口径复测”量化展示，不是搜索平台或模型厂商的官方排名；比较前后结果时应固定诊断版本、项目、问题、模型、样本数和采样方法。

页面的 AI 成本收据逐次展示内容生成、优化、确实调用模型的平台适配和真实可见度采样所用的 provider、模型、输入/输出 Token 及价格快照。模型没有返回 usage 时显示“未知”，未配置已核对单价时显示“未定价”，不会假装为 0。账号登录、上传和发布本身不调用模型时没有“发布 Token”；最终费用以供应商账单为准。

## 5. 备份工作区

应用发现已有非空数据库时，会在启动阶段先生成一份经过完整性检查的 SQLite 快照。登录后也可点击标题栏“立即备份”。数据库快照在：

```text
%LOCALAPPDATA%\GEOContentPlatform\backups
```

默认保留最新 5 份。该快照只包含 `geo.db`，不包含素材、账号会话和登录配置。做完整迁移时：

1. 先点击“立即备份”。
2. 退出工作区并关闭窗口。
3. 确认程序进程已结束。
4. 复制整个 `%LOCALAPPDATA%\GEOContentPlatform` 到受保护位置。

账号会话与回答原文可能包含敏感信息，不要上传到公共网盘、工单或聊天群。

## 6. 修改口令与退出

点击右上角“管理员”：

- “修改本机口令”要求输入当前口令、新口令和确认值；新口令仍执行首次设置时的强度规则。
- “退出工作区”会清除当前会话并回到登录页。

修改口令不会删除项目、文章或历史。当前版本不会保存旧口令，也不支持明文找回。不要为“重置密码”而直接编辑或删除 `auth.json`；该文件还包含会话签名密钥，错误操作可能破坏登录状态。

## 7. 媒体账号与发布中心

### `safe` profile

`safe` EXE 强制关闭真实发布，桌面导航不展示媒体账号与发布中心。真实执行入口和旧版直接发布入口都会在加载发布器前拒绝，调度器也以禁止真实发布的模式启动。这不是故障，也不能通过修改 Windows 环境变量绕过。

### `authorized_real` profile

启动时软件先检查 Google Chrome，并让内置的 Playwright、Patchright 驱动各打开一次纯本地离线页面。两个探针都成功后，媒体账号与发布中心才进入可用状态；失败时不会假装已经具备发布能力。

首次使用按以下顺序操作：

1. 打开“媒体账号”，为目标平台填写账号标识，然后点击“添加 / 登录”。
2. 软件会弹出该平台的浏览器、二维码或登录终端。由账号持有人亲自完成扫码、验证码和平台确认；软件不会绕过风控。知乎人工登录最多等待 10 分钟，窗口可能被挡在软件后面，请同时检查桌面和任务栏并保持 Chrome 窗口打开。
3. 点击“检测登录”，确认账号状态为已连接。
4. 在发布中心选择文章、平台和素材，并为每个平台明确选择发布账号。软件会按渠道预检标题和正文，为受限字段生成留有安全缓冲的可编辑平台版本；界面展示原稿字数、实际发送字数、平台上限和软件安全线。原稿不变，发布器也不会再把标题或正文静默截断。确认任务前应人工检查语义是否完整；平台规则可能随时变化，预检不是平台接收保证。
5. 账号卡片会展示各渠道的保守单日建议数量和操作间隔，执行前也会提示扫码、短信验证码、滑块或人工确认等常见验证。它们是软件的运营参考，不是平台官方额度，不能保证不触发风控。运营者仍须遵守平台协议并自行承担限流、处罚或封禁风险。
6. 立即发布时，再次核对确认框中的实际发送标题、正文、账号和素材。可输入单任务确认短语执行一项，也可勾选当前页任务并输入明确的批次确认短语；批次按列表顺序逐项执行，一项失败、需验证或待核验不会拦住后续项，也不会自动重试失败项。真实定时任务到点后只会进入队列，当前版本不做无人值守外发；到点后仍须人工确认。Demo 定时任务可以自动演示，但不会访问任何平台。
7. `processing` 表示发布器正在调用平台，此时不能重试或核验。只有调用已经结束、但平台没有给出可核验成功或失败证据时，任务才进入“已提交、待平台核验”。先检查平台作品、审核和草稿记录；若选择“未发布”，必须确认发布/登录窗口及旧执行已经停止、至少等待 5 分钟并完成后台检查，之后才可把任务收口为失败再重试。“核验平台结果”只登记本机状态，不会再次点击发布。

Bilibili 当前只支持视频。EXE 不包含也不会下载 `biliup`；`authorized_real` 只会识别本机默认目录中经过固定版本、文件大小、SHA-256 和离线版本探针共同校验的 `biliup 1.2.4`。通过后点击登录会弹出独立的 Bilibili 扫码终端，软件最多等待十分钟，不会刚弹窗就判定失败；上传返回 BV 号时自动记为成功，未返回可核验 BV 号时保留为待核验。未知版本不会执行。软件会登记本次登录、凭据读取和上传进程，正常结束、取消、超时、异常或退出桌面软件时只清理这些受控进程树，不按名称结束无关程序。该方式属于本机已核验的外部兼容运行时，不随 GEO 分发；正式商用仍应优先走 Bilibili 官方开放平台和单独的权利审核。

## 8. 升级与卸载

升级前关闭软件并完成整个数据目录备份，然后校验并替换 EXE。数据不在 EXE 旁边，正常替换程序不会自动删除 `%LOCALAPPDATA%\GEOContentPlatform`。

卸载程序只需在退出后删除 EXE。本机数据会继续保留；只有在确认无需恢复且已有有效备份后，才删除整个 GEO 数据目录。

## 常见问题

### 软件提示已经运行

相同数据目录有单实例锁。切换到已有窗口；若看不到窗口，在任务管理器确认旧进程确实结束后再启动。

### 窗口空白或无法初始化

确认系统有可用的 Microsoft Edge WebView2 Runtime，然后重新启动。若仍失败，查看 `logs\desktop.log`。

### 忘记管理员口令

当前 Beta 没有恢复通道。保留整个数据目录不动，联系维护人员处理；不要反复修改 `auth.json` 或用新文件覆盖它。

### 登录尝试被限制

连续失败会触发本机频率限制。停止尝试，等待响应提示的时间后再用正确口令登录。

### 媒体账号登录没有完成

新版登录弹窗会区分浏览器启动、平台验证和本地保存三个阶段，并显示安全的错误代码与下一步。需要结束时使用弹窗里的“结束本次登录”；若 Chrome 仍在运行，再手动关闭它。知乎登录的详细本机诊断记录在 `logs\zhihu.log`，登录线程异常记录在 `logs\login.log`；日志不会写入 Cookie 值或文章正文。

### 发布任务一直显示处理中或待核验

“处理中”只代表软件仍在执行平台调用，不应同时点击重试或核验。若软件或浏览器异常退出，下次启动会把中断任务转成“已提交、待平台核验”，而不是自动重发。检查平台的作品、审核和草稿记录；只有确认相关窗口和旧执行已停止、等待至少 5 分钟并完成后台检查后，才选择“未发布”并重新执行，避免同一内容重复发送。

### 可见度结果看起来不合理

先检查品牌主名、产品名、别名、竞品和原始回答，再展开逐样本证据。结果只代表本次导入的回答，不代表整个模型、市场或时间段；要比较趋势，应固定问题和采样方法并增加样本。

当前指标属于 `metrics-ad-hoc-python-1.1.0` 临时口径，不能与 provider grounding 结果或历史 TypeScript 指标直接做同比、环比。

### 为什么手工回答区填写了 qwen-plus 却没有调用千问

因为手工回答区的“模型标识”只是溯源标签。若要调用模型，必须使用同页的“受控真实采样”，填写完整 HTTPS 服务地址、精确模型 ID、当前软件会话 API Key 和 1–5 次样本数，核对只外发 prompt 的清单并显式确认。缺少任一项时软件不会联网；当前也不会定时、后台或分布式采样。

### 为什么看不到发布中心或发布按钮不可用

先查看 manifest 的 `publishing_profile`。`safe` 构建按设计永久关闭真实发布；`authorized_real` 构建还要求 Google Chrome、Playwright/Patchright 成品探针和媒体账号状态全部就绪。软件会显示具体阻塞原因，不能通过手工设置环境变量绕过。Bilibili 还需要 EXE 外部的固定版本兼容运行时通过 SHA-256 与离线版本探针；不满足时只禁用 Bilibili，不影响其他已就绪渠道。
