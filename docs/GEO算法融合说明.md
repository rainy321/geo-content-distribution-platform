# GEO 算法融合说明

> 适用范围：当前 Windows EXE 分支。本文说明同事交接包中的算法资产如何被审查、移植和产品化，不代表直接运行原 TypeScript SaaS，也不代表任何 AI 平台承诺收录或引用。

## 1. 结论先行

同事交接包里最有价值的部分不是页面或云端基础设施，而是两类可复用算法：

1. **发布后测量**：从 AI 回答中识别品牌、竞品、位次、引用、来源、情感与置信度，再给出有证据的改进建议。
2. **发布前约束**：用确定性的查询意图矩阵定义“用户会怎样问”，用内容结构和证据契约约束文章，再在生成后执行可引用性门禁。

当前 EXE 已经采用第一类能力；本轮继续采用第二类能力，形成以下闭环：

```text
项目事实
  -> 查询意图矩阵
  -> GEO 内容蓝图与证据边界
  -> 文章生成/改写
  -> 可引用性门禁
  -> 平台发布
  -> AI 回答采样
  -> 提及/位次/引用/SOV/置信度
  -> 证据化建议与复测
```

这里的“算法融合”是**按当前 Python + Vue + Windows 桌面架构进行的可追溯移植**，不是把两个项目直接拼接，也不会引入交接包的云端租户、支付和分布式运行环境。

| 平台变体 | 上游内容结构原则 + 当前 EXE 已有平台发布约束 | 同一事实蓝图按各平台安全字数、内容形态和字段限制编译；平台裁剪不能改变事实或制造新证据。 | 避免超长卡住，同时保持跨平台实体和核心主张一致。 |

本轮是**原则与契约级移植**，不是逐行复制：上游 `content-draft-1.0.0` 的 200,000 字符通用输出上限不适合直接拿来做媒体发布限制；当前 EXE 仍以各平台更严格的长度与字段约束为最终门禁。上游查询建议里的 `brandMode`、`funnel`、`freshnessNeed`、`importance`、`templateId` 和 `rationale` 也没有伪装成当前接口已完整保留的字段；本机版使用自己的 `intent/cohort/priority` 契约。

当前本机可引用性规则版本为 `ai-citeability-rules-2.1.0`，通过线为 75 分，并保持与旧 GEO 分数分离。七个维度及权重为：直接回答 20、实体一致性 15、证据可追溯 20、结构可提取 15、语义覆盖 10、FAQ/决策支持 10、风险卫生 10。即使总分达到 75，只要存在“标准品牌名缺失”“无来源的绝对化主张”或“无来源的量化效果主张”等 P0 问题，仍不能通过。高风险主张只能由结构化证据中的显式 `claim` 同时关联具体实体和主张后解除阻断；来源标题、任意邻近 URL 或模型生成的标题/链接不能单独充当证明。

## 4. 当前算法如何量化

产品中必须把三个分数分开，不能合并成一个看似精确的“采集率”。

| 阶段 | 指标回答的问题 | 不能代表什么 |
| --- | --- | --- |
| 发布前可引用性 | 文章是否具备清晰实体、直接答案、问题覆盖、结构化片段、证据和限制说明 | 不代表页面已经被抓取、建立索引或被某个模型引用 |
| 发布后 AI 可见度 | 在本次明确问题和样本里，品牌是否被提及、排名如何、是否被引用、相对竞品 SOV 如何 | 不代表整个市场、全部用户或全部模型的长期表现 |
| 置信度 | 当前结果在既定样本协议下有多稳定 | 不代表事实正确率，也不是未来提升概率 |

推荐优先级沿用同事算法的核心形式：

```text
priority = expected_impact × confidence × business_importance / max(effort, 0.25)
```

它用于安排“先改什么”，不是预测收入。上游规则建议内容/引用问题一般在 21 天后复测、站点审计问题一般在 14 天后复测；短时间演示只能作为基线与流程验收，不能宣称已经产生因果提升。

## 5. 可对客户展示的真实说法

可以说：

- “系统把品牌事实、用户问题、内容结构、证据边界和平台约束编译成可审计的文章蓝图。”
- “发布前会给出可引用性门禁和具体整改项，发布后按固定问题采样并量化提及率、引用率、位次、SOV 与置信度。”
- “每个分析结果带算法版本、样本证据和来源溯源，可以复测和比较同一口径下的变化。”
- “该流程提高内容被检索与引用的准备度，并帮助团队找到最值得修复的缺口。”

不能说：

- “达到某个 GEO 分数就保证被豆包、千问、DeepSeek 或其他模型收录/采用。”
- “一次短测证明模型已经训练了我们的内容。”
- “回答出现品牌名就证明引用了官网。”
- “手工填写的 provider/model 标签证明回答确实来自该平台。”
- “显式 URL 一定可访问、一定支持相邻主张，或一定由模型真实检索得到。”
- “少量成功回答可以代表平台总体成功率或市场总体份额。”

更准确的商业表达是：**软件提高可抓取、可理解、可检索、可引用的内容准备度，并用受控样本测量结果；最终抓取、索引、检索和引用由各平台独立决定。**

## 6. 数据、调用与安全边界

- 内容蓝图、查询意图矩阵和可引用性门禁是本机确定性处理，不需要把客户项目发送给外部模型。
- 内容生成是否外发、发送哪些字段，以生成确认页和当前模型配置为准；已有客户数据不得用于未授权的真实验收。
- AI 可见度手工导入接口不联网；受控采样只发送操作员确认的 prompt，并把返回文本交给本机分析器。
- 可见度分析不调用媒体平台；媒体发布也不应自动触发 AI 采样。
- URL 分类不进行网络请求；不得把“允许引用的 URL”误写成“已经核验的证据”。
- 真实发布门禁只评分发布器实际发送的标题和正文；未随平台副本发送的摘要、生成回执来源不会给发布副本加分。正文中的本机、内网、保留域名、非法端口或其他非公网 URL 会直接阻断。

## 7. 验收和回滚要求

本轮能力只有同时满足以下条件，才能在成品中标为“已启用”：

1. 查询矩阵对相同输入确定性输出、去重、有数量上限；没有竞品时不生成虚假竞品问题。
2. 生成提示词只使用项目明确提供的事实；证据不足时要求披露限制，禁止虚构外部链接和业绩。
3. 可引用性门禁返回独立版本、分数、通过标记、P0 阻断项和可操作整改建议；分数达线但存在 P0 问题时仍不通过。
4. 原有 GEO 评分、内容生成、诊断、可见度分析和发布流程保持兼容。
5. 自动化测试不访问真实模型、不登录媒体平台、不执行真实发布。
6. Windows EXE 重打包后完成启动、API 健康、页面资源和离线关键路径验收。

回滚时保持两层解耦：可以停用新的内容编译/门禁并回到原生成路径，而不删除已经保存的文章、成本台账或可见度历史；发布后分析器仍能独立处理手工导入样本。任何版本迁移都必须保留 `algorithm_version`，不得静默改写历史分数。
